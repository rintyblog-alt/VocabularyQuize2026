# AI 問題生成（4 択以外を作れるようにする）

「画面には 125 形式あるのに、AI は 4 択しか作らない」を直すための土台。

---

## 1. 4 択に寄っていた原因

1 か所ではなく、**4 か所すべて**が 4 択を前提にしていた。

| どこ | 何が起きていたか | いま |
|---|---|---|
| **サーバの JSON Schema**（`preset-draft.schema.json`） | `type` の enum が **37 種類**しか無かった。プリセット生成は構造化出力（JSON Schema で文法を縛る）なので、**enum に無い形式は、モデルが書きたくても書けない**。配分では 98 形式を選べるのに噛み合っていなかった | **93 種類**へ拡張。あわせて `checkPreset` の判定表（選択式 16 / 必要な部分 37 / 記述 18 / カード 4）もそろえた |
| AI へ渡す形式の一覧 | 形式 **ID の羅列**だけ。何に向く形式かを渡していなかった | `qdescriptor.js` が「ねらい・使う場面・避ける場面・返し方・採点」を渡す |
| 配分 | 何をどれだけ作るかを決めずに丸投げしていた | `blueprint.js` が先に決める。決まりごと（§12）を満たすまで通さない |
| 取り込み | `correctAnswer` しか見ておらず、正しく作れている 4 択も捨てていた | `isCorrect` / `correctIndex` も受ける |
| 教材との相性 | 画像が無いのに画像問題を頼んでいた（作れないので落ちる） | 教材を解析し、作れない形式は**理由つきで**先に外す |

**「AI へ 153 形式の名前を渡す」は解ではない。** 渡すほどトークンを食い、
使い分けの手がかりが無いので結局 4 択へ戻る。**先に絞って、絞った理由を持つ**。

画像が要る形式は enum へ入れていない。**AI は素材を作れないため**
（架空の画像 URL を書かせない）。教材に画像があるときでも、
座標を当てる問題を AI に作らせるのは別の話なので、いまは手で作る形式のまま。

**音声は入れている。** 音声ファイルではなく **原稿（`script`）を書かせる**からで、
音は解くときに読み上げで用意する（`ui/tts.js`）。詳しくは「9. 音声問題」。

> Schema を変えたときは **Bridge の再起動が要る**（起動時に読み込むため）。

## 1-b. まだ残っていた「1 形式に寄る」（2026-08-04 の実測で判明）

上の 4 か所を直しても、**実 AI では 1 形式に寄っていた**。単体テストは全部通っていた。

`node vqpresettype.cjs`（ローカル Qwen3-VL-30B・資料 約 2,000 字）:

| 頼んだ内訳 | 返ってきたもの |
|---|---|
| 単語入力3 / 空欄2 / 並び替え2 / カード1 / 記述1 / 組合せ1 | **単語入力 10 問**（1 形式） |
| 4択4 / 単語3 / 空欄1 / カード1 / 記述1 / 組合せ1 / 並び替え1 | **短答 12 問**（1 形式） |
| 正誤 8 | 正誤 8 問 ✅ |
| 4択4 / 単語2 / 空欄1 / カード1 / 組合せ1 / 並び替え1 | 4択 4 / 単語 6（2 形式） |

分かったこと。

- **1 回の依頼で複数の形式を頼むと、モデルはほぼ 1 形式へ寄せる。**
- **1 形式だけを頼めば、そのとおりに作る。**
- 「問1: 単語入力 / 問2: 空欄 …」と 1 問ずつ名指ししても直らなかった。
  むしろ単一形式の指定まで崩れた（正誤 8 問 → 4 択 8 問）。
  だから **1 問ずつの割り当ては、形式が 2 種類以上のときだけ**書く。

### やったこと — モデルと戦わず、合わせる

全体の配分は変えないまま、**1 回の依頼へ入れる形式を 1〜2 種類に絞り、回をまたいで配る**。

```
全体: 4択5 / 単語3 / グラフ2 / 空欄2 / カード2 / 記述2 / 組合せ2 / 並替2
  回1: 4択 5
  回2: 単語入力 3 / グラフ読み取り 2
  回3: 単一穴埋め 2 / カード 2 / 短文記述 1
  回4: 短文記述 1 / 組合せ 2 / 並べ替え 2
```

- 配る関数は `qplan.take(plan, n)`（`MAX_TYPES_PER_ROUND = 2`）。
- `preset-studio` は **最初に全体ぶんの配分を 1 回だけ決め**（`st.__planPool`）、
  回ごとにそこから取り出す。毎回 `planMix(n)` を呼び直すと、
  どの回も同じ内訳になり、モデルはそれを 1 形式へ寄せてしまう。
- 回帰: `client/v2/tests/qplan-round.test.mjs`（14 件）

### 配ったあとの実測（同じ条件・同じ資料）

| 条件 | 配る前 | 配ったあと |
|---|---|---|
| 4 択禁止・10 問 | 単語入力 10（**1 形式**） | 単語入力3 / 空欄2 / 記述1 / 組合せ1（**4 形式**・7 問） |
| 5 形式以上・12 問 | 短答 12（**1 形式**） | 4択5 / 単語3 / 空欄1 / カード1 / 記述1 / 並替1（**6 形式**・12 問） |
| 記述を除外・10 問 | 4択4 / 単語6（2 形式） | 4択4 / 単語2 / 空欄1 / 組合せ1 / 並替1（**5 形式**・9 問） |
| 全体 | 4 形式 | **7 形式**。4 択は 47% |
| 保存できた | **0 / 4 件** | **3 / 4 件** |

保存が通るようになったのは、出典の形をそろえたから（上の「出典」の項）。

### まだ残っていること（正直に）

- **単一形式の指定が、たまに守られない。** 「正誤だけ 8 問」を 2 回測って、
  1 回は正誤 8 問、もう 1 回は 4 択 8 問になった。回ごとにぶれる。
  作り直しはしない（同じになることがあり時間だけ増える）。
  代わりに **`qplan.compare()` で突き合わせ、違ったらその場で出す**ようにした。
  黙って受け取らない。
- **並べ替えとカードは、まだ落ちることがある。** 実測では
  「items が空」「back が無い」で取り込めなかった。
  受け取る側（`fromAi`）は名前の揺れを広く受けるようにし、
  依頼文にも「必ず書くこと」を名指しで足したが、**この 2 つは再測定していない**。
  サーバの Schema 側（`preset-draft.schema.json` の `items` は中身を縛っていない）で
  縛るのが本筋。Schema を変えたら Bridge の再起動が要る。

## 2. いまの流れ

```
指示文 ＋ 教材
   ↓ ① 何を頼まれたのか        blueprint.extractRequirements()
   ↓ ② 教材に何があるのか      blueprint.analyzeContent()
   ↓ ③ 作れる形式はどれか      blueprint.candidates()  ← capability.forAi() で絞る
   ↓ ④ 何をどれだけ・なぜ      blueprint.build() / qplan.planMix()
   ↓ ⑤ 偏っていないか          blueprint.validateDistribution()
   ↓ ⑥ AI へ頼む              qplan.promptFor()（形式の説明 ＋ 内訳 ＋ 1 問ずつのねらい）
   ↓ ⑦ 取り込む                qplan.importAll()
   ↓ ⑧ 解けるか・点をつけられるか  answerability.check()
   ↓ ⑨ 保存・出題の直前にもう一度  validate（requireAnswerable）
```

問題文を書かせる **前** に④まで済ませているのが要点。
ここを飛ばすと、何度プロンプトを直しても 4 択へ戻る。

## 3. 配分の決まりごと（§12）

ユーザーが「4 択だけ」と言っていない限り、4 択だけにはしない。

| 問題数 | 最低の形式数 |
|---|---|
| 5 問以上 | 2 形式 |
| 10 問以上 | 4 形式 |
| 20 問以上 | 6 形式 |
| 30 問以上 | 8 形式 |

- 同じ形式は全体の **4 割**まで
- 選んで答える形式は合わせて **半分**まで
- **守れないときは黙って通さない。** 「この教材から作れる形式が N 種類しかない」と書く

`enforceDistribution()` が足りない形式を足し、多すぎる形式を減らす。
足したことも減らしたことも `notes` に残る。

## 4. 形式を選ぶ理由（§13）

教材の中身（用語・定義・年代・手順・因果・分類・数値・本文・会話・表・図・画像・音声・語彙・主張）
ごとに、向く形式を並べてある（`TYPE_FOR_FEATURE`）。
選んだ理由は 1 問ずつ `reasonForType` に入り、画面にも出る。

**分からないものを「無い」と決めない。** 教材のことが何も分からないときは
`known: false` とし、画像だけは頼まない（作れないため）。
音声は教材の中身ではなく「その端末で音を出せるか」で決まる。

## 5. 使えない形式を頼まれたとき（§14）

**黙って 4 択へ置き換えない。** 理由と代わりを出す。

```
「図へのラベル配置」は教材に画像がないため使えません
代わりに使えます：部位名のマッチング／画像選択／単語入力
```

画面（プリセット作成 → 「形式を選ぶ」）でも、生成のログでも同じことを出す。

## 6. 解けるか・点をつけられるか（§20 / §21）

形として正しくても、人が解けないものがある。

- 並べ替えに同じ項目があり、正しい順が 2 通りある
- 組み合わせの相手がいない／右側に同じ文が 2 つある
- 問題文の中に正解がそのまま書いてある
- 記述なのに採点の観点が無い
- 画像の外に正解の場所がある／的が小さすぎて指で押せない
- 読み上げる原稿も音声も無いのにリスニングをさせる
- 原稿に「〜が正解です」と書いてあり、**そのまま流すと答えが聞こえる**

`answerability.js` が形式ごとに見る。**2 か所で効かせる。**

1. 取り込みのとき（`qplan.importAll`）… 通らないものは理由つきで落とす。全部は捨てない
2. 保存・出題の直前（`validate` の `requireAnswerable`）… 書きかけの間は指摘しない

`capability.js` が 1 形式ずつ実際に試す。
**名前があることと、使えることは別。**

```
node vqcapability.cjs   →  capability-matrix.md
node vqcontract.cjs     →  contract-report.md（本番 110 形式の契約テスト）
```

実測（2026-08-03）：**125 種類中 本番 110 / ベータ 8 / 準備中 7 / 未対応 0**。

本番と判定した 110 形式は、実画面で次を **すべて** 通している（`vqcontract.cjs`）。

空の問題を作れる / 見本を作れる / 保存・出題の検証を通る / 解ける・点をつけられる /

Insight で日本語の名前になる / スマホでも表示できる

1 つでも落ちた形式は本番にしない。

## 9. 音声問題（リスニング・書き取り）

### 決めたこと

**音声ファイルではなく「原稿（`script`）」を問題の本体にする。**

| こうすると | こうなる |
|---|---|
| AI は原稿だけ書けばよい | 架空の音声 URL を作らない |
| 音は解くときに用意する | 声を変えても問題を作り直さなくてよい |
| 原稿は問題に残る | 配られた側の端末でも解ける（端末の読み上げに落ちる） |

### 音の出どころ（上から順に試す）

1. 端末に貯めてある音声（IndexedDB `vq2.audio`。上限 120MB、古いものから消す）
2. Bridge で作る（VOICEVOX 118 / Kokoro 54 ＝ 172 声。外へは送らない）
3. 端末の読み上げ（Web Speech API）… **落ちたことを画面に出す**（声が変わるため）

### 声の決まり方

問題（`q.voice`）→ プリセット（`preset.audio.voice`）→ 言語ごとの既定
（日本語 `voicevox:3` / それ以外 `kokoro:af_heart`）。速さも同じ順。

### 形式ごとの扱い

| 形式 | 原稿 | 備考 |
|---|---|---|
| リスニング選択・発音選択・会話応答・一度だけ再生・倍速 | `script` | 無ければ 4 択へ寄せる（記録を残す） |
| 音声穴埋め | `script` ＋ 空欄 | 無ければふつうの穴埋めへ寄せる |
| ディクテーション | `correctAnswer` がそのまま原稿 | 試験モードでは原稿へ写してから正解を消す |

### 気をつけたこと

- **原稿に解説を混ぜさせない。** そのまま音になるので、答えが聞こえてしまう。
  指示で止め、`answerability` の `scriptLeaksAnswer` でも拾う（警告・捨てない）。
- **鳴らせない端末では音声形式を配分に入れない。** 判定は `qplan.NEEDS[type] === "speech"`
  の 1 か所だけ。教材に音声があるかは見ない（原稿から作れるため）。
- **進み具合のふりをしない。** 音の長さが分かるとき（`X-Audio-Seconds`）だけバーを進め、
  分からない読み上げでは流れるだけにする。
- 独自ヘッダは `Access-Control-Expose-Headers` に書かないとブラウザから読めない。

### 測ったこと（2026-08-03・無料のローカルモデル）

| | 結果 |
|---|---|
| 声 | 172（日本語 118・英語 28・その他 26） |
| 音の生成 | 日本語 3.2 秒の音を 0.43 秒 / 英語 0.31 秒 |
| 書き取りの生成 | 3 回とも作れた（原稿つき・解ける） |
| リスニング選択の生成 | **3 回とも原稿を書かず、4 択へ寄せられた** |

リスニング選択が安定しないのはモデルの側の問題で、しくみは通っている
（原稿を手で書けば、そのまま鳴って解ける）。有料モデルでの再測定が要る。

## 頼んだ出題形式を、最後まで守る（2026-08-04）

「正誤問題だけで 8 問」と頼んでも 4択 8 問が返る、という報告。実測すると
**3 か所**で形式が入れ替わっていた。1 か所直しても次で戻るので、全部そろえる。

| どこで | 何が起きていたか | どう直したか |
|---|---|---|
| 指示文の読み取り | レジストリ名が「○×」「単一穴埋め」で、人が書く「正誤問題」「空欄補充」と当たらず、読み取った形式が **0 個** | `blueprint.js` の別名表を増やした。打ち消し（「4択は使わないで」）も要求と取り違えない |
| 生成（AI） | `type` の enum に 100 種類あるので、文章でいくら頼んでも model は好きに選べる。`questionType` は自由文字列で素通り | `preset-generator.mjs` の `fmtWithTypes()` で、その回に作ってよい形式だけを **両方の enum に残す** |
| 直し（AI） | 生成のあとに走る `preset-patcher` が **format 無し**で、○× を 4択に書き換えていた（raw-trace で確認） | Patcher にも同じ enum をかけ、`applyPresetPatch` は `type` / `questionType` を上書きしない |

その先の**取り込み**でも形式が変わっていた。

* ○× は `correctAnswer: "正しい"` だけ返すことが多く、選択肢が 2 つ未満だと
  短答へ落としていた（8 問中 5 問）。○× の選択肢は決まっているので補う。
  補ったときは正解もこちらで決め、AI の書いた正解を重ねて読まない
  （読むと書き方しだいで **両方に印が付き**、保存できなくなる）。
* 組み合わせは `pairs:[{left,right}]` 以外の書き方（`items:[{term,meaning}]` など）を
  丸ごと捨てていた。同じ意味の書き方は受ける。

回帰テスト: `client/v2/tests/prompt-format.test.mjs`（15）、
`client/v2/tests/qplan-source.test.mjs`（23）、実 AI は `vqprompt.cjs`。
