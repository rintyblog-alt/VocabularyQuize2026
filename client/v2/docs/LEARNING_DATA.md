# 学習データの統合と Insight

「クイズを解いても、どこにも積み上がらない」を直すための土台。

---

## 1. 何が起きていたか

学習の結果は、3 か所へ**別々に**落ちていた。

| どこから | どこへ | 誰が読んでいたか |
|---|---|---|
| これまでのクイズ（HAND / CHOICE） | `wordPractice.analytics.sessions.v1` | ホーム・旧 Insight |
| 新しいクイズ画面 | `vq2.results.v1` | 結果画面だけ |
| Quick Mock | `vq2.results.v1` | 結果画面だけ |

つまり **新しいクイズと Quick Mock は、ホームにも Insight にも出ていなかった。**
Insight が「記録がありません」の巨大な空白になっていた本当の原因はこれ。

---

## 2. いまの流れ

```
結果を保存する（VQ2.store.results.put）
   ↓ ここ 1 か所に結線してある
VQ2.learning.recordResult()
   ├ LearningSession  … 1 回の学習（出どころ・モード・点・時間・形式の内訳）
   ├ LearningAnswer[] … 1 問ずつ（正誤・点・時間・科目・単元・形式）
   ├ LearningEvent    … 何が起きたか（同じことが 2 回来ても 1 回）
   ├ 日次の集計       … その日だけ作り直す
   └ 旧形式へ 1 行    … ホームと旧 Insight がそのまま読める
   ↓
VQ2.analytics … 概要 / 推移 / 科目 / 単元 / 形式 / モード / 苦手 / 習慣 / 試験 / おすすめ
   ↓
Insight（vq-insight）
```

**結線は「保存の出口 1 つ」に付けてある**（`learning.install()`）。
呼び出し側は 5 か所（クイズ・試験・AI 採点の確定 ×3）あるので、
1 か所ずつ足すと必ずどこかを忘れる。

---

## 3. 決めごと

- **二重に数えない。** セッションの id は結果の id から決まる。
  同じ結果を何度保存しても 1 本のまま上書きされる。
- **AI 採点待ちを 0 点として確定しない。**
  `pendingCount` として別に数え、正答率の分母にも入れない。
  確定して保存し直すと、そこで初めて点に入る。
- **答えの中身は保存しない。** 正誤・点・時間・科目・単元・形式だけ。
  答案そのものは結果レコードにある。分析に要らないものは持たない。
- **分からないものを作らない。** 時間が残っていない・単元が無い・形式が
  分からない、は `null`。推測値を本当の値として保存しない。
- 日付の境目は端末の時計（日本の利用者なら JST）。
- 学習記録を消すと、日次の集計と旧形式の行からも消える。

---

## 4. これまでの記録

`entry.js` の起動時に 1 度だけ取り込む（`vq2.learn.backfill.v1` で済んだ印を付ける）。

- 保存済みの結果（`vq2.results.v1`）→ すべて学習セッションへ
- これまでのクイズ（旧形式）→ `source: "legacy"` として。
  **1 問ずつの記録は作らない**（残っていないため）。形式・単元は `null`。

---

## 5. Insight（ホームとの違い）

| | ホーム | Insight |
|---|---|---|
| 目的 | 今日の学習を始める | 長い目で傾向を見る |
| 期間 | 今日・今週 | 7日 / 30日 / 90日 / 今年 / 全期間 |
| 中身 | 続きから・今週の時間・最近のクイズ・苦手トップ3 | 前期間との比較・推移・科目と単元・形式・苦手の理由・試験・習慣・おすすめ |

Insight にしかないもの：

- **前の期間との差**。比べる相手が無ければ **0% と出さず、理由を書く**
- 科目 → 単元のドリルダウン
- 問題形式ごとの正答率・得点率・平均時間・ヒント率・飛ばし率
  （**解いた形式だけ**。登録されている 125 種類を並べない）
- 苦手とその**理由**（正答率・直近の落ち込み・平均との差・時間・ヒント・飛ばし）
- 試験（Quick Mock）だけの分析
- 曜日・時間帯（**記録が少ないうちは「まだ判断できません」**）
- おすすめ（実データからのみ。無ければ出さない）

初期の期間は、記録が 5 回以下なら「全期間」、それ以上なら「30日」。
30 日を出して巨大な空白にしないため。

グラフだけで伝えない。同じ数字を必ず表（「数字で見る」）にも出す。

## 6. 問題形式の実態（Capability Matrix）

`domain/capability.js`。**名前があることと、使えることは別。**
1 形式ずつ実際に試して、次がそろっているかを見る。

空の問題を作れる / 保存の検証を通る / 編集できる / 表示できる / 採点できる /
結果で再現できる / AI へ渡す形がある / 日本語の名前がある / 紙にできる

```
node vqcapability.cjs   →  capability-matrix.md（人が読む表）
```

実測（2026-08-03）：**125 種類中 本番 110 / ベータ 8 / 準備中 7 / 未対応 0**。
AI へ渡しているのは **98**（試験に使えるものは **69**）。

`qplan.planMix()` はここで許された形式からしか配分を作らない。
AI が使えない形式を返したら、同じ操作の形式へ寄せるか、その 1 問だけ捨てる
（**全体を失敗させない**）。

## 7. AI の仕事の台帳（AIJob）

`domain/aijob.js`。通信そのものは `VQ2.ai`（Bridge へのストリーミング）のまま。
ここは「何をしていて、どこまで進んで、何が残っているか」だけを持つ。

- 状態：待ち / 実行中 / 人の判断待ち / 完了 / 失敗 / 取り消し
- **偽の進捗を作らない。** 届いた段の位置か、実際に数えられる件数からしか出さない
- **失敗しても途中結果を捨てない。** どこで止まったかも残す
- 失敗した場所からやり直せる（`retry`。最初からやり直すことも選べる）
- 同じ操作を 2 回押しても 1 件（`startKey`）
- 画面を離れて止まった仕事は「実行中」のまま残さない（`reconcile`）
- 人へ出す文に技術的な文言を出さない（「できた 8 問は残しています」）

## 8. テスト

| コマンド | 内容 |
|---|---|
| `node client/v2/tests/learning.test.mjs` | 統合・二重計上・採点待ち・互換・日次・苦手・習慣（70 件） |
| `node client/v2/tests/aijob.test.mjs` | 仕事の台帳・形式の実態・配分（39 件） |
| `node vqinsight.cjs` | Insight の実画面（PC・スマホ / 66 件） |
| `node vqcapability.cjs` | 形式の実態を実画面で測る＋表の書き出し（16 件） |
| `node vqchain.cjs` | AI 出力 → 取り込み → 保存 → 受験 → 採点 → Insight（23 件） |

### 消してはいけない確認

- 「同じ結果を保存し直しても増えない」
- 「採点待ちを不正解として数えない」
- 「くらべられないときは理由を書く（0% と出さない）」
- 「作り話の数を出さない」「作り話の図を描かない」
- 「AI へ渡すのは本番のものだけ」
- 「偽の進捗を作らない」
- 「失敗しても途中結果は残る」
