# VocabuQuiz Learning Workspace V2

教材を「学習コンテンツと試験」へ変換し、作成 → 受験 → 採点 → 分析 → 復習 → 共有までを
VocabuQuiz の中だけで完結させるための基盤。

既存の画面・データ・AI 基盤は一切置き換えていない。V2 はすべて Feature Flag の内側にあり、
OFF にすると本体は V1 のまま動く。

---

## 3. Feature Flag

| フラグ | 何が変わるか |
|---|---|
| `presetStudioV2` | 新しいプリセット作成画面（AI 編集・差分適用・Undo） |
| `quizPlayerV2` | 新しいクイズ画面（集中モード・自動保存・再開） |
| `resultViewV2` | 新しい結果画面（分析・復習プリセット作成） |
| `quickMockV2` | 試験作成（MockSpec・配点調整・品質分析） |
| `quickMockPdfEngine` | 問題冊子・解答用紙・正解解説の紙面生成 |
| `quickMockDigitalExam` | デジタル受験（問題冊子と解答用紙の同期） |
| `quickMockAiGrading` | 記述問題の AI 補助採点 |
| `quickMockFeedSharing` | 結果の FEED 共有 |

既定はすべて ON。`quickMock*` の子フラグは `quickMockV2` が OFF なら自動的に OFF になる。

切り替え方:

```
URL       ?vq2=all            全部 ON
          ?vq2=off            全部 OFF
          ?vq2=presetStudioV2,quizPlayerV2   個別に ON
コンソール VQ2FLAGS.setAll(true) / VQ2FLAGS.set("quickMockV2", true)
画面       Library ページ上部の「Learning Workspace」→「設定」
```

URL の指定は保存されるので、リロードしても維持される。

## 3.5 入口（どこから開くか）

本体の見えている UI は 2 つの Shadow DOM で出来ている。入口はその中へ足す。

プリセットの一覧は本体の「プリセット」画面が唯一の正規の場所。V2 は一覧を持たない。

| 場所 | 何が起きるか |
|---|---|
| 左サイドバー「Learning Workspace」 | プリセットを作る／結果と分析／Quick Mock（試験） |
| サイドバーとプリセット画面の「クイズを作成」 | Preset Studio V2（新規） |
| プリセットのカードを押す | **プリセットの詳細**（中央シート） |
| カードの「開始」 | Quiz Player V2 をそのまま開く |
| 設定 →「Learning Workspace」 | 8 つのフラグの ON/OFF と、作ったものの件数 |

### プリセットの詳細（`vq2-preset-detail`）

全画面を奪わない中央シート（モバイルでは下から出る）。出すのは実データだけで、
無い項目は行ごと出さない。

- 上：バナー画像・アイコン・名前・説明
- 中：問題数／内訳／教科／タグ／作成者／作成日／更新日／公開範囲
- 中：解きかた（モード・出題数・1 問あたりの秒数・全体の制限時間・ランダム化）
- 右下：削除／編集／クイズを開始

**削除**は本体の削除処理へ渡す（確認もアプリ側のものを 1 回だけ出す）。
消えたのを見届けてから V2 側の記録も片づける。V2 にしか無いものはこちらで確認して消す。

### 見た目（アイコン・バナー）

Preset Studio の「プリセットの設定」で決める。絵文字 22 種から選ぶか、画像を選ぶ。

- 画像は端末の中で縮小してから `data:` URL で持つ。**外部 URL は受け付けない**
  （読み込み先が消える／閲覧が追跡されるため）。外へ送信もしない。
- 上限はアイコン 200KB・バナー 700KB。品質と寸法を落として収める。
  収まらなければ保存させず、大きさを数字で伝える。
- V1 の保存領域にも往復で保たれる。設定していないプリセットに空の項目を生やさない。

旧 `#appLibraryPage` は現在の UI では `visibility: hidden` で隠れている。
そこにも入口を残してあるが、それは新 UI が無効（`body[data-ui-v2] != "1"`）のときの保険。

フラグを OFF にすると入口はその場で消え、「クイズを作成」は元の導線へ戻る。

### 画面は重ねない

V2 の画面はどれも全画面なので、**同時に開くのは 1 枚だけ**。`U.mount()` は
新しい画面を出す前に、開いている画面をすべて畳む。クイズ → 結果 → 復習 と辿っても
下に前の画面が残らない。元の画面へ戻る前提のもの（Feed 共有・プリセットの設定）だけ
`stack: true` を指定する。

`U.mount(id, { sheet: true })` で中央シートになる（全画面ではなく、背景が見えたまま）。
モバイルでは下から出るシートに変わる。プリセットの詳細と、プリセットの設定がこれ。

### 確認ダイアログも重ねない

プレビュー・設定・保存・閉じるの確認は、**1 つの画面につき同時に 1 枚だけ**（`U.dialog`）。
ボタンを続けて押すと同じ確認が何枚も重なり、いちいち閉じないと先へ進めない状態になっていた。

- 同じ内容の要求 → すでに出ているものを前に出し、**同じ Promise を返す**
- 別の内容の要求 → 前のものを畳んでから出す。**前のものは決着させない**
  （中途半端に `false` を返すと、呼び側の「破棄して閉じる」側へ落ちる）

実測（`vq2studio.cjs`）: プレビュー 6 連打で 1 枚、設定シート 5 連打で 1 枚。

## 3.6 AI パネル（Preset Studio と Quick Mock の右側）

**Preset Studio と Quick Mock は同じ部品を使う**（`U.AiChat` / `U.markSvg`）。
書き写すと、片方だけ直した差が必ず出る。見た目・動き・時間表示はここ 1 か所で決まる。

Quick Chat と同じ形にしてある。上が会話、下が入力欄。
**Quick Chat そのものではなく、同じ Orchestrator を呼ぶ別の入口**（混ぜると Quick Chat が壊れる）。

作っている最中の手順は会話の中に 1 行ずつ積む。行は追加ぶんだけ DOM へ足すので、
新しい行だけが 220ms でふわっと出る（`prefers-reduced-motion` では動かさない）。

### 手順は 1 行ずつ出す（一気に出さない）

Orchestrator は処理の切れ目で状態をまとめて送ってくる。素直に描くと 4〜5 行が
一瞬で出て、そのあと数十秒なにも動かない。何が進んでいるのか分からないので、
届いた順に**間を空けて 1 行ずつ**出す（`revealQueue`）。

- 間隔は溜まり具合で変える（4 行以下 320ms / 5〜8 行 140ms / それ以上 60ms）。
  実際の進み具合から遅れないようにするため
- 終了・失敗・停止のときは溜まっているぶんを**全部出しきる**（`flushRevealAll`）
- `prefers-reduced-motion` では間を空けずに出す

### 経過時間と見込み時間（右上）

動いているあいだは上に細い帯（`.vq2-runbar`）を出す。左に「いま何をしているか」、
右に「経過」「残り およそ N 分」「done / total」。

見込みは **実際に終わった回の所要時間の中央値**からだけ出す。
まだ 1 回も終わっていないうちは「残りを計算しています」と出し、**数字は出さない**
（当てずっぽうの残り時間を見せない）。1 回に作る数が途中で半分になったときは
予定回数も引き直す。

1 秒ごとに書き換えるのは数字だけ（`paintEta`）。パネルごと描き直すと入力中の文字が消える。
同じ理由で、生成中の本文も `#aiStream` の中身だけを書き換える。

### はじめの画面

まだ何も話していないときは、VocabuQuiz の印（インライン SVG・外部読み込みなし）と
一言だけを中央に置く。輪がゆっくり回り、V が引かれる。一言は 7 つのテンプレートから
5.2 秒ごとに入れ替わる。`prefers-reduced-motion` では止まる。

### 会話はプリセットごとに残す

`vq2.presetChats.v1` に **プリセット id ごと**に保存する（`ST.saveChat` / `loadChat`）。
下書き（`drafts`）と違い、**保存しても閉じても消さない**。次に同じプリセットを開くと
前回のやり取りと作業ログがそのまま出る。

- 利用者ごとに `ownerId` で分ける。他人の会話は読めない
- 溢れないよう古いものから落とす（1 プリセット 80 発言 / 1 回 300 行 / 60 プリセット）。
  落とすのは古いほうだけで、**直近は必ず残る**
- プリセットを削除したときだけ、そのプリセットの会話も消す

### 資料の添付

読み取りは既存の添付部品（`window.__vqChatFiles`）にそのまま任せる。V2 では作り直さない。
API は `add(files)` / `list()` / `remove(id)`（`addFiles` や `attachments` は**無い**）。

- 対応: PDF（ページごとに抽出）・画像・DOCX・ZIP・テキスト／コード
- 読み取りは非同期なので、**終わるまで待ってから** AI へ渡す（最大 3 分）
- 渡すのは読めたものだけ。画像は data URL の本体を `imageBase64` として渡し、Vision で読ませる
- 何を読み取ったか（ページ数・行数・画像）を入力欄の上に出す。外すこともできる
- 指示文と資料は**同時に**渡る。分割生成では毎回すべての資料を渡し直す

実測（`vq2attach.cjs`）: 資料だけに書いた架空の固有名詞が、
PDF＋テキストで **8 / 10 語**、画像だけで **8 語** 問題文に現れた。

### 先に「何を問うか」を決めてから作る

1. 資料と指示を受け取る
2. **1 回だけ**資料を読み、問える論点を洗い出す（`AI.planTopics`・実測 6 秒）
3. 各回は「この論点について 1 問ずつ」と指定して作る。論点は毎回違うので重複しない
4. 論点を渡した回は `skipDocumentAnalysis` を立て、資料の要点のまとめ直しを省く
   （着眼点は論点が供給する。実測 11 秒/回の節約）
5. 論点が 2 個未満しか取れなければ、これまでどおりの作り方へ自動で戻る

論点の洗い出しには **`taskHint: "summarization"` を必ず付ける**。付けないと
ルーターが「問題を作って」と読んで構造化生成の重い経路を通り、
論点ではなく問題と集計表が返る（実測 112 秒 → 6 秒）。
取り出しは `VQ2.draft.parseTopics()`（箇条書きの行だけ・表や選択肢は捨てる）。

**実測**: 4 ページ 145 秒・37 ページ 177 秒。どちらも 20 / 20 問。

### 記述・論述・英作文には採点基準を必ず付ける

この 4 形式（`long_answer` / `essay` / `english_writing` / `source_analysis`）は
コードで正誤を出せないので AI が採点する。ただし **採点基準（Rubric）が無いと
AI 採点そのものを行わない**（根拠を示せない採点はしない、という決まりのため）。

基準が空のままだと、解いても**永久に未採点のまま残る**。実際そうなっていた。
`draftToQuestions` が採点基準を作っていなかったので、AI が作った記述問題はすべて
そのまま出て、結果画面は `pendingAi` を捨てて何も起きずに終わっていた。

いまは 3 か所で必ず用意する。

| いつ | どうする |
|---|---|
| AI が問題を作ったとき | AI が基準を出していればそれを使う。無ければ `S.defaultRubric(type, points)` |
| 編集画面で形式を記述へ変えたとき | 基準が無ければ下敷きを作る |
| 配点を変えたとき | `S.rescaleRubric` で比率を保ったまま合計を配点へ合わせ直す |

- 合計は**必ず**配点と一致させる（一致しないと保存時に error になる）
- 配点より基準の数が多いときは、重いものだけを残す（0 点の基準を並べない）
- 編集画面で基準の追加・削除・文言・配点・観点を直せる（`.vq2-rub`）
- AI の出した合計は信用しない。**基準ごとの内訳の合計**を得点にする（`applyAiGrade`）
- 基準の配点上限を超えた採点は上限で止め、`requiresReview` を立てる
- 確信度が 0.7 未満のものは自動確定しない

実測（`vq2studio.cjs`・ローカル AI を実際に呼ぶ）: 10 点の記述に片側しか書けていない
答案を出したところ、**4 / 10 点**（内訳 `r2:4/4` `r1:0/6`）を 5 秒で返し、
基準ごとに点をつけた理由が付いた。基準を外した同じ問題では採点せず、
「採点基準が無いため採点していません」と理由を返した。

### 問題数が多いときは分けて作る

1 回で 20 問作らせると、後半が前半の焼き直しになり重複が増える（実測 11 問）。
そこで **5 問ずつ**に分け、毎回「すでに作った問題」を渡して重複を避ける。

- できたぶんから順に画面へ出る。途中で止めてもそこまでは残る
- 重複は問題文を正規化して照合し、こちらで落とす（件数をログに出す）
- 足りなければ追い足す。2 回続けて増えなければ打ち切り、理由を出す
- **数の指定が無いときは 10 問**を既定にする（数を決めずに投げると、資料が多い人ほど
  1 回の出力が膨らんで上限に当たるため）。既定で作ったことはログに出す
- 実測: 資料なし **20 / 20 問・150 秒**

**問題数は全角でも読む。**「２０問」と打つ人のほうが多い。半角しか見ていなかったため
指定を取りこぼし、分割が働かないまま 1 回で全部作らせて上限に当たっていた。
読み取りは `VQ2.draft.parseCount()` に置いてテストで固定してある（サーバ側の
`requestedCount()` も同じく全角を読む）。

### 出力が上限で切れたら、自動で小分けにする

資料をたくさん入れるほど 1 問あたりの出力が膨らみ、上限で JSON が途中終了する。
そのときは**その回の数を半分にして続ける**（5 → 2 → 1）。

- 途中で減らしたことはログに出す
- 1 問ずつでも収まらなければ、資料を減らすか範囲を絞るよう伝えて止める
- ここまでに作れた問題は捨てない

サーバ側は `options.questionCount`（指示文からも読む）に合わせて出力上限を伸ばす
（1 問あたり 900 トークン）。固定の 6144 トークンのままだと JSON が途中で切れ、必ず失敗する。

## 3.7 Quick Mock（試験）

### 大問ごとに分けて作る

1 回で試験まるごとを作らせると、資料が多いほど出力が長くなり、
**途中で JSON が切れて全部失う**。しかも後半ほど解説や出典が抜ける。

そこで構成案の大問ごとに 1 回ずつ呼ぶ。1 回が短いので失敗しにくく、
1 つの大問が失敗しても**他の大問は残る**。

- 1 回あたりの設問数は `MAX_PER_CALL = 6` で頭を打つ
- 構成案が読めなければ、大問数と設問数から機械的に割る
- 2 つめ以降は `skipDocumentAnalysis`（何を出すかは構成案が決めている）
- 毎回「すでに作った設問」を渡して重複を避ける
- 出力上限は `questionCount` に合わせて伸ばす（伸ばさないと必ず途中で切れる）

**構成案は表でも読む。** AI は `| 大問 | 内容 | 配点 | 問数 |` の形で返すことが多い。
表を読めないと「構成案を読み取れませんでした」になり、分割生成の計画が立たない
（実際にそうなっていた）。見出し行と区切り行は捨て、`30` / `30点` / `5問` のどれでも読む。

### 問題の不備を残さない

AI は資料が多いほど、問題は書けても **解説・出典・正解** を落とす。
落ちたまま試験にすると、受験者のところで
「解答欄が出ない」「採点できない」「見直しができない」という形で出る。

三重に止める。

| 段 | どこ | すること |
|---|---|---|
| 1 | サーバ（`mock-draft.schema.json`） | `answerKey` と、その中の `explanation` を**必須**にする。構造化出力なので、必須にすれば書かざるを得ない（`preset-draft.schema.json` は最初から `correctAnswer` と `explanation` を必須にしていた。試験側だけが緩く、ここが抜けの元だった） |
| 2 | サーバ（`verifyMockDraft`） | 正誤問題の選択肢なしを **high**、解説なしを medium として検出し、差分修正へ回す |
| 2b | サーバ（`mock-generator`） | **資料があるときは `sourceReferences` も必須にする**。任意のままだとモデルは書かない（実測: プリセット 3/3 に対し試験 0/7）。書かせたうえで、存在しない番号は `resolveSources` が落とすので架空の出典は残らない |
| 3 | 手元（`MB.repairSpec`） | 機械で直せるものを直す。**内容は作らない** |

`MB.repairSpec` が直すもの:

- 正誤問題に選択肢が無い → 「正しい／誤っている」を用意し、解答の文字から正解を立てる
- 選択肢はあるが正解が立っていない → 解答の文字・記号（①ア A 1）から書き当てる
- 選択肢が 1 つしか無い選択問題 → 短答へ落とす（空の選択肢を並べた解答欄を出さない）
- AI が採点する形式に採点基準が無い → `S.defaultRubric`
- 直しても足りないものが残る設問は、必ず `requiresReview` を立てる

残った不備は `MB.auditSpec` が問ごとに並べ、確認画面へ出す。

- **AI に補ってもらう**（`AI.repairQuestions`）— 足りない設問の、**足りない項目だけ**を書かせる。
  問題文は変えない。すでにある解説や正解は上書きしない。
  資料名の分からない出典は取り込まない（**存在しない出典を作らない**）
- **受験できない N 問を外す**（`MB.dropQuestions`）— 番号と回答欄を振り直し、配点を残りへ割り振り直す。
  解答欄の作れない設問を受験者に出すより、外して伝えるほうがよい

### 資料をたくさん入れても止まらない

- **読み込めない画像が 1 枚でもあると、処理全体が落ちていた**（エンジンが 400 を返す）。
  いまは画像が原因のエラーなら**画像を外して 1 度だけやり直す**（`ModelRunner`）。
  他の資料まで巻き添えにしない。外したことは利用者に伝える
- **頼んだ数を大きく超えて作ってくる**ことがある（実測: 4 問頼んで 48 問）。
  大問ごとに頼んだ数で切る。切ったことはログに出す
- 1 つの大問が失敗しても、次の大問へ進む。できた大問はすべて残る

実測（`vq2stress.cjs`・資料 8 本 48 ページ相当 ＋ 画像 2 枚 = 36KB）:
**4 / 4 大問が通り、100 点ぴったり・解答欄 100%・正解 100%・解説 100%・出典 100%・残る不備 0 問**。

### 受験画面に解答欄の無い問題を出さない

`answerInputHtml` は**絶対に空を返さない**。選択肢が 2 つ未満なら、
文字で書ける欄と「この問題は選択肢が用意されていません」を必ず出す。
保存の検証（`requireAnswerable`）でも、正誤問題の選択肢なしは error にして通さない。

## 4. ビルドとロールバック

```bash
# 生成して client/index.html へ注入（冪等）
node client/v2/build-v2.mjs

# 注入を丸ごと取り除く（V1 のみの状態へ）
node client/v2/build-v2.mjs --remove
```

3 段階で戻せる:

1. **フラグ OFF** — `?vq2=off`。入口が消え、V2 は一切動かない。データは残る。
2. **注入の除去** — `--remove`。`<script id="vq2-app">` ごと消える。
3. **バックアップ復元** — `client/v2/dist/index.beforeV2.bak.html` と
   `client/_backup_v2_<日時>/index.html`。

Orchestrator 側だけを戻したい場合は `local-ai/config/models.json` の
`orchestrator.enabled` を `false` にして Bridge を再起動する（既存の仕組み）。

## 5. 旧データとの関係

- V2 のデータは専用キー（`vq2.*`）に保存する。
- 既存の `wordPractice400.presets.v1` は **読み取り** と **追記のミラー** にのみ使う。
  既存プリセットの中身を書き換えることはない。
- V2 で保存したプリセットは V1 の形へ変換して同じキーへ追記するので、
  既存のクイズ画面・ライブラリからもそのまま使える。
- V2 でプリセットを削除しても V1 側のデータは消さない（利用者のデータを失わせないため）。
- V1 は `cards` が空なら `words` を読む。この解釈順を V2 も守る。
  `words` だけのプリセットを V2 に通しても `cards` を勝手に生やさない。

**V1 の足切りに合わせている点**（本体 `normalizeCardEntry` の実装に合わせた実測対応）:

- カードの `id` は正の整数でなければ V1 に捨てられる。V2 の文字列 ID は書き戻し時に
  未使用の最小の正整数へ振り直す。もとから正の整数だったものは動かさない。
- `front` か `back` が空のカードも捨てられる。正解の本文 → 正答 → 別解 → 解説の 1 行目、
  の順で埋め、どれも無い記述式には「（記述式）」という形式名を入れる（内容は捏造しない）。

## 6. セキュリティ

- **他利用者のデータ**: すべてのレコードが `ownerId` を持ち、読み出しは現在の owner で絞る。
  他人のレコードは一覧に出さず、上書き・削除もできない。
- **AI 生成物は未信頼**: 紙面へ流し込む文字列はすべてエスケープしてから組む。
  資料内に `<script>` や `onerror` が書かれていても実行されない（E2E で実測確認）。
- **資料内の指示に従わない**: Prompt Injection は Orchestrator 側で検出する。
  UI 側でも命令文をそのまま実行しない。
- **秘密の思考過程**: Vision 検査・採点・分析のいずれも、構造化された結果だけを保存する。
  Chain of Thought は保存も表示もしない。
- **コンパイル**: 組み込みレンダラはブラウザの中だけで動く。外部プロセスを起動せず、
  シェルも呼ばない。外部 URL も取得しない。
- **Local AI Bridge**: 既存の制限（127.0.0.1 限定・Origin 制限・Token 認証・
  本番オリジン非許可）をそのまま維持している。V2 は新しい口を開けていない。

## 7. AI の使い分け（§32）

| 処理 | 思考レベル | 理由 |
|---|---|---|
| 1 問だけの軽い書き換え | fast | 検証が要らない |
| プリセット生成・修正 | normal | 構造化出力＋検証 |
| 試験の構成案 | normal | 文章のみ |
| 試験本体の生成 | deep | 複数資料を横断する |
| 記述 1 問の Rubric 採点 | normal | 1 回のモデル呼び出し |
| 学習分析 | normal | 集計済みの入力 |
| 試験全体の品質分析 | deep | 全設問を横断して見る |
| 紙面検査 | normal | 計測結果からの判定 |

Deep を常用しない。実測の所要時間は [TEST_REPORT.md](TEST_REPORT.md) を参照。

## 8. 計測（§34）

`AIUsageEvent` を記録するが、**制限はかけていない**。正式な上限値が決まっていないため、
利用者に残量を表示することもしない。記録内容は Library →「Learning Workspace」→「設定」で見られる。

記録する種別: `chat_message` / `preset_generation` / `preset_revision` / `mock_generation` /
`mock_revision` / `document_analysis` / `image_analysis` / `pdf_typesetting` / `pdf_compile` /
`pdf_visual_review` / `ai_grading` / `result_analysis` / `export_generation`

`estimatedComputeUnits` はモデル呼び出し数・ページ数・画像数・コンパイル回数・
所要時間から機械的に出す相対値で、課金には使わない。
