# VocabuSpeak（英語の学習ワークスペース）

左パネルの **Speak** から開く。`client/v2/ui/speak.js` が画面、
`client/v2/domain/speak-*.js` が中身、`speak-content/` が教材のもと、
`client/content/english/` が配る形。

---

## 1. いちばん大事な分け方

| | 何を持つ | いくつ |
|---|---|---|
| **Content Atom** | 学ぶ「中身」。英文そのもの | 1 英文につき 1 つ |
| **Exercise Variant** | その中身を「どう出すか」 | 1 英文から 8〜9 通り |

同じ英文でも、聞く・書き取る・埋める・並べ替える・訳す・話すでは別の学習になる。
**だから Atom は 1 つのまま、Variant を増やす。**

`familyId` は「言い方が違うだけで同じことを言っている」ものをまとめる。
出題のとき、同じ family を続けて出さないために使う。

```
familyId: cafe_order_basic
  I'd like a coffee, please.
  Can I have a coffee, please?
  Could I get a coffee?
```

**やってはいけないこと**（`speak-content/build.mjs` が守る）
- 音声の話者や選択肢の順だけを変えて、別の教材として数える
- 同じ英文を別 ID にして水増しする

---

## 2. 出題の決まりごと（`speak-select.js`）

上から順に強い。

1. まだ出していない Variant をいちばん先に出す
2. 同じセッションで同じ Variant を出さない
3. 同じセッションで同じ英文（Atom）は原則 1 回まで
4. 同じ family を続けて出さない
5. 同じ日に同じ Variant を出し直さない
6. 未出題が残っている間は、覚えたものを出し直さない
7. すべて出し終えたら復習へ移る

**規則 1 は規則 3 より強い。** 同じ英文の縛りだけで未出題が出せなくなったら、
そこだけ緩めて「同じ英文を別の出し方でもう一度出します」と伝える。
黙って覚えた問題へ戻らない。

選び方は完全ランダムではなく重み付け。ただし **同じくらい良いものの中だけ**で引く
（件数だけで上位 N を切ると、未出題が尽きかけたときに覚えた問題が混ざる）。

出した理由は 1 問ずつ残り、画面にも出る。

| 理由 | いつ |
|---|---|
| はじめての問題 | 履歴が無い |
| 復習の予定日になっています | `nextReviewAt` を過ぎた |
| 前に間違えた問題 | 誤答がある |
| しばらく出していない問題 | 最後の出題から日が経った |
| 同じ英文の、まだやっていない出し方 | 英文は既習・その出し方は未習 |

## 3. 教材を作る

```bash
node speak-content/build.mjs           # 作る
node speak-content/build.mjs --check   # 書き出さずに検証だけ
node speak-content/build.mjs --report  # 内訳を詳しく
```

```
speak-content/seed/*.json      人が書いた英文（en / ja / family / タグ / よくある誤り）
        ↓ Variant 展開        1 英文 → 8〜9 通り
        ↓ 検証                英文・日本語訳・正答・レベル・読み上げやすさ
        ↓ 重複検出            完全一致 / 記号をそろえると一致 / 意味が近い
        ↓ 索引づくり
client/content/english/        curriculum.json ／ index/{level}/{cat}.json ／ {level}/{cat}/{lesson}.json
```

**1 つのレッスンが壊れても、他のレッスンを失わない。** 作れなかったものは
外して理由を報告に残す。1 文だけ落とすこともある（レッスンごと落とさない）。

重複の扱い:
- 完全一致・記号だけの違い → **消す**
- 意味が近いだけ → **残す**（言い換えとして役に立つ）。ただし family をまとめ直す助言を出す

## 4. 教材を読み込む（`speak-content.js`）

**全部をクライアントへ送らない。**

| 取りに行くもの | 大きさ | いつ |
|---|---|---|
| `curriculum.json` | 7.5 KB | 開いたとき 1 回 |
| `index/{level}/{cat}.json` | 約 12 KB | そのカテゴリーを使うとき |
| `{level}/{cat}/{lesson}.json` | 約 110 KB | 選ばれた問題があるレッスンだけ |

索引の 1 行は名前つき JSON ではなく 6 個の値の配列にしてある
（`[variantId, atomId, familyId, activityType, lessonId, difficulty]`）。
レベルとカテゴリーは置き場所から分かるので行に入れない。

## 5. 問題の出し方（既存のものを使う）

**VocabuSpeak 専用のレンダラーや採点は作っていない。**
`speakModel.toQuestion()` が Variant を V3 の問題へ翻訳し、
そのまま `question-renderer` と `evaluator` に渡す。

| VocabuSpeak の形式 | 使う既存形式 |
|---|---|
| リスニング選択・会話理解 | `audio_choice` |
| ディクテーション | `dictation` |
| 音声穴埋め / 英文穴埋め | `audio_fill_blank` / `fill_blank` |
| 英文並べ替え | `reorder_english` |
| 和文英訳 / 英文和訳 | `translate_en` / `translate_ja` |
| 誤文訂正 | `error_correction` |
| 表現選択 | `choice_best` |
| フラッシュカード | `flashcard` |
| リピート・発音練習・シャドーイング | `read_aloud_check` / `pronunciation_score` / `shadowing`（**未完成**） |

音は原稿（`q.script`）から作る。**架空の音声 URL は作らない。**
声とレベルごとの速さは `ttsConfig` → プリセットの設定 → 言語ごとの既定 の順。

## 6. 話す（聞き取り・発音・会話）

### 聞き取り（STT）

```
native/stt/        faster-whisper（base.en / int8 / CPU）
                   venv 217MB ＋ モデル 141MB。TTS の venv とは別（壊さないため）
src/stt/index.mjs  必要になってから起こす。127.0.0.1 のみ
/stt/transcribe    音を生のまま受ける。**話した中身をログへ残さない**
```

実測（M3 Max・CPU）: **2 秒の音を 0.4 秒**で文字にする。

**目標の英文を手がかり（initial_prompt）として渡さない。**
渡すと目標文の一部を頭に付け足したり、「Mhm. Mhm.」のような言っていない語を
並べたりした。発音の採点では、目標へ引きずられた文字起こしは点を甘くするだけ。

### 発音の採点（`pronounce.js`）

**音素はやっていない。** 端末にあるのは目標文と文字起こしだけなので、
測れるものだけを、**混ぜずに**出す。

| | 何を見るか |
|---|---|
| 伝わりやすさ | 目標の語をどれだけ言えたか（語の対応づけ） |
| はっきりさ | 拾えた語を、聞き取りがどれだけ迷わず拾ったか。**音素の正しさではない** |
| 流暢さ | 話す速さと、途中の間 |

- 数字の言い方をそろえる（`ten thirty` ↔ `10.30`）。そろえないと全部ばつになる
- **目標と違うことを言ったら、速さがよくても高得点にしない**（上限 = 伝わりやすさ+25）
- 聞き取りの自信が低いときは **点をつけず、やり直しを勧める**（発音のせいにしない）

実測（Kokoro の音を STT へ通した通し）:

| 言ったこと | 総合 |
|---|---|
| 目標そのまま | 97 |
| 1 語だけ違う（station → stadium） | 90 |
| まったく違う文 | 58 → **上限をかけて 50** |

### 録音（`ui/stt.js`）

- マイクは押したときだけ開き、使い終わったら必ず閉じる
- 30 秒で自動的に止める（押しっぱなし防止）
- **録音は既定ですぐ消す。** 残す設定にしたときだけ端末内（IndexedDB）に置き、
  期限が来たら消す。**外へは送らない**

### シナリオ英会話（`dialogue.js`）

固定の分岐で進み、**分からないときだけ** LLM に「どの意図か」だけを聞く。
LLM に会話を作り直させない。読み上げるのは英語のセリフだけ。

- 始める前に **行き先の無い分岐**が無いか確かめる（途中で止まる会話を出さない）
- 分からないときは **進めずに聞き返す**
- **言っていないミッションを達成にしない**
- LLM が言ってきた意図でも、**その場面に無い分岐は受けない**
- 見分けに `please` のような機能語を使わない
  （使うと「please」と言っただけで「サイズを言った」ことになる）

### まだ無いもの

| | 状態 |
|---|---|
| 音素ごとの発音評価 | **無い**。画面でもそう書いている（ベータ表示） |
| 自由英会話（テーマを決めて自由に話す） | **無い**。画面で「まだ作っていません」と出す |
| 会話後の文法添削・言い換え提案 | **無い** |

## 8-b. 学習プレイヤーの共通の枠（2026-08-04）

レッスン中の画面は、通常クイズと **同じ設定**を読む。
文字の大きさ・本文の幅・詰まり具合・動きは `VQ2.playerPrefs` が持ち、
`PS.applyVars(app.root)` を `render` / `renderRun` / `renderSpeak` / `renderTalk` の
先頭で呼んでいる。→ `client/v2/docs/LEARNING_PLAYER.md`

VocabuSpeak 固有のものは、この枠へ押し込まない。

| 足したもの | なぜ |
|---|---|
| レッスン中の「設定」ボタン | 字幕や速さを変えたいのは、たいてい聞いている最中だから |
| 大きな丸いマイク（`speakBigMic`） | 片手で持って話すので、下の真ん中に大きく置く。設定で普通の大きさへ戻せる |
| 録音中の「やめる」（`sp-rec-cancel`） | 「止める」しか無いと、言い間違えても必ず一度採点される。**やめたぶんは採点も保存もしない** |
| 結果の「練習の種類ごと」 | 数えられたものだけを出す。発音・流暢さ・文法は話す練習でしか測れないので、空欄を並べない |
| 結果の「できていたところ／次に直すところ」 | **いま数えた結果からしか書かない**（作文しない）。2 問以上で 80% 以上／60% 未満 |
| 結果の「次におすすめ」 | 実際に押せるものだけ（間違えた問題の復習・次のレッスン） |

## 9. 画面を作るときの決まりごと

- **配線は入口で 1 回だけ**（`wireOnce`）。`U.on` は呼ぶたびに聞き手を足すので、
  描き直すたびに配線すると 1 回押しただけで何度も動く。
  音が何重にも鳴って割れていたのは、これが原因だった。
- `U.button` に `iconOnly: true` を渡すときは **`label` を渡さない**（文字がはみ出す）。
  代わりに `aria` を使う。
- 問題文は `QR.promptHtml()` が作る。`QR.html()` は答える場所しか作らない。
  ただし誤文訂正は答える場所が本文を出すので、promptHtml 側では出さない。
- **色だけで伝えない。** 輪にも棒にも数字を添える。
- シートの幅は既定 680px。内訳を並べる画面は `mount({ css })` で広げる（880px）。
