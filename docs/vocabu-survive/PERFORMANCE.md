# 速さ

## 測り方の 前提

検査の 端末は **SwiftShader**（絵を CPU で 描く）。
だから 「1 秒に 何枚」は 実機の 目安に ならない。
代わりに **端末に 依らない 数**だけを 線引きに 使う。

| 測る もの | なぜ 端末に 依らないか |
|----------|---------------------|
| 1 コマの JS の 時間 | 考える 時間。GPU が 速くても 変わらない |
| 描き回数 | 何回 GPU に 話しかけるか。多いと どの 端末でも 遅い |
| 面の 数 | 送る 頂点の 量 |
| 落とす 量 | 回線の 話 |
| メモリ | 端末の 余裕 |

## いまの 数（`node vqsurviveperf.cjs`）

いちばん 重い コース（c29 最後の試練・8 人）で 測った。

| | 机の上 (1440×900) | 机の上 最高 | スマホ (390×844) | 低い端末 |
|---|---|---|---|---|
| 段 | high | ultra | medium | low |
| 板 | 1092×896 | 1092×878 | 366×786 | 275×590 |
| 影 | あり | あり | あり | **なし** |
| 1 コマの JS 中央 | **1.8ms** | 1.8ms | **1.0ms** | 1.0ms |
| 95% | 2.5ms | 2.7ms | 1.4ms | 1.3ms |
| 描き回数 | 26 | 28 | 26 | 29 |
| 並べた / 捨てた | 326 / 278 | 455 / 149 | 178 / 426 | 130 / 474 |
| 面 | 29,844 | 42,132 | 15,666 | 8,522 |
| メモリ | 33.5MB | 40.1MB | 45.2MB | 40.1MB |

60 枚/秒 なら 1 枚 16.7ms。JS が 1.8ms なので **GPU に 15ms 残る**。

## 落とす 量

| | 生 | 圧縮後 |
|---|---|---|
| VocabuSurvive の 束 | 219KB | **69.5KB** |
| （参考）Babylon.js | 約 4,500KB | 約 1,100KB |

旧 VocabuSurvival v1/v2 は Babylon.js を 前提に していて、
その Babylon が どこにも 無かったので **起動しても 例外で 止まっていた**。

束ねないと 34 本の 取りに行きに なる。細い 回線（実測 1.2Mbps）だと それだけで 数秒。

★ `--charset=utf8` も 試した。生は 219→212KB に 減るが
**圧縮後は 69.5→71.0KB と 逆に 増えた**。流れるのは 圧縮後なので ascii の まま。

## 効いている 工夫

| 工夫 | 効果（実測） |
|------|-------------|
| まとめ描き（instancing） | 326 個を **26 回**で 描く |
| 視界の 外を 捨てる | スマホでは 604 個 中 **426 個**（70%）を 捨てる |
| LOD 3 段 | 遠い ものは 面が 1/4〜1/10 |
| 形を 10 種類に 絞る | 形が 増えると まとめられない。30 種類なら 描き 30 倍 |
| 段（低/中/高/最高） | 低で 面 8.5k・影なし・画素 0.75 倍・上限 90 万画素 |
| 隠れて いる 間は 板を 触らない | 1×1 に 縮んで 戻ると 1 コマ 潰れた 絵が 出る |
| 置き換え前提の 数の道具 | 毎フレーム 新しい 配列を 作らない（ごみ＝カクつき） |
| 音は その場で 作る | 音源ファイル 0 バイト |

## 開くまで

| | 冷えた 1 回目 | 2 回目 以降 |
|---|---|---|
| タブを 押して 開くまで | 4.2 秒 | **0.4〜1.1 秒** |

★ 1 回目が 遅いのは **本体の JS 5.8MB（vq-core 2.4MB・vq2-app 3.0MB）との 取り合い**。
VocabuSurvive 自身の 束は 219KB で、取りに行きは 100ms 未満。
線は そちらに 引いてある。

## まだ できること
