## 3. 直した不具合

すべて**再現を確かめてから**直した。推測だけの修正はしていない。

### 3-1. 読めない画像が 1 枚あると、全部が 2 秒で全滅する

構成案・試験作成に画像を混ぜると、エンジンが 400 を返して処理全体が落ちていた。

原因は 2 つ重なっていた。

1. 画像エラーの判定が `e.message` しか見ていなかった。
   `err(code, detail)` は **message に定型文**を入れ、**detail に実際の中身**を入れる。
   つまり肝心の "Failed to load image" は `detail` 側にあり、一度も一致していなかった
2. 気づけるよう直したあと、今度は**役割ごとに毎回**画像で再試行し、予算を使い切った

→ `detail` も見るようにし、一度画像を落とすと決めたら
`_dropImages` で**その実行中は二度と積まない**ようにした。
利用者には「読み込めない画像があったため、画像を外して続けます」と出る。

回帰テスト 4 件（`local-ai/tests/model-runner.test.mjs`）。

### 3-2. 解答が空のまま、埋め直しが走らない

```js
const keys = new Set((d.answerKey || []).map((a) => a.id));   // ← 旧
```

解答を「**あるか**」だけで見ていた。モデルは `answer: ""` を返すことがあり、
これは JSON Schema の `required` を**満たしてしまう**。
そのため不備と見なされず、埋め直しの round が一度も走らないまま、
**保存の段になって初めて** `emptyAnswer` で落ちていた（8 件中 1 件・3 問）。

→ 中身のある解答だけを「済み」と数える（`local-ai/src/schemas/index.mjs`）。
これで `answer_missing`（high）が立ち、**既存の埋め直し経路に乗る**。
`pipeline-structured.mjs` の数え方も揃えた。

回帰テスト 6 件（`local-ai/tests/check-mock.test.mjs`）。
`answer:""` が JSON Schema だけでは止まらないことも、テストとして固定した。

**修正後の再測定（3 条件・36 問）: `emptyAnswer` は 0 件**（修正前は 1 条件で 3 件）。

ただし**正解の欠けが完全に無くなったわけではない**。
再測定では別の形で 1 件出た（`noCorrectChoice` — モデルの書いた解答が
どの選択肢の文言とも一致せず、`repairSpec` が書き当てられなかった）。
これは今回直した経路とは**別の不具合**で、**未解決**。

### 3-3. 選択肢の足りない選択問題で、保存できなくなる

プリセット作成 17 件目で、15 問のうち **12 問**が「選択肢 1 つ以下の選択問題」で返ってきた。
そのままだと `choiceCount` で弾かれ、**1 問ずつ手で直すまで保存できない**。

→ `draftToQuestions` で短答へ落として**残す**（捨てない）。
回帰テスト（`draft.test.mjs` 53 件）。

### 3-4. `stop.sh` が Bridge を止め損ねる

`local-ai` の中から `node src/server.mjs` で起動すると、プロセスの引数は
`local-ai/src/server.mjs` にならない。`pkill -f` のパターンが外れ、
**動いているのに「起動していません」**と言って止め損ねていた（実際に踏んだ）。

→ 待ち受けポートの持ち主を先に見て確実に止める。止まらなければ強制終了。

## 3-b. 試したが効かず、戻したもの

### 矛盾した答案が、黙って満点で通る

「幕府は十分な恩賞を与えていた**が**、…恩賞が足りなかったからである」に
2 回とも 10/10・確信度 0.8・要確認なしが付いた。

減点はさせず**確信度を下げて要確認へ落とす**指示を足し、30 答案で測り直した。

| | 隣まで一致 | 要確認 | 矛盾答案（2 回） |
|---|---|---|---|
| ① 足す前 | 90% | 3.3% | 10/10・10/10 |
| ② **足した** | **83.3%** | 6.7% | **10/10・10/10** |
| ③ 戻したあと | 93.3% | 3.3% | 6/10・10/10 |

**狙った答案は 1 件も要確認にならなかった。効果を確かめられなかったので戻した。**
効かない変更を「対応済み」として残さない。

一致率は同じ条件でも 83.3%〜93.3% で揺れるため、②が悪化させたとも言い切れない。
言えるのは「矛盾答案には効かなかった」ことだけ。
この限界は `V3_KNOWN_LIMITATIONS.md` に残した。

## 4. 試験そのものの不具合（製品ではない）

正直に分けて書く。**製品が落ちたのではなく、試験のほうが落ちていた**もの。

### 4-1. 受験の流れと紙面が実行できていなかった

`vq3mock.cjs` が、**保存できなかった回の id** を掴んでいた。
8 件目（わざと無理な条件・保存拒否）の id で `ST.mocks.get` を引くので、当然見つからない。

→ 保存が通った回の id だけを使う。未実施のときは**「未実施」と明記**する。
黙って飛ばすと、通ったように見えてしまう。

**直したあとに実行できた**（`mock-verify.json`）。

- 受験 → 提出 → 結果: 10 問すべてに解答 → **26 / 50 点**（コード採点 10 問・満点も一致）
- 紙面: **組み込みレンダラは使える**。Typst・LaTeX は**未導入**（表示どおり）

あわせて `plan.pages` を数えていたのも直した。`buildPlan` が返すのは
`pages` ではなく **`booklets`**（問題冊子・解答用紙・解答解説）なので、
何ページあっても常に `null` になっていた。

### 4-2. 添付の枚数の数え方が古かった

`vq2attach.cjs` が「2 ファイル → chip 2 個」を期待していた。
いまの Quick Mock は 2 ペインで、**右の入力欄**に本体を、
**左の設定ペイン**に控えを映すので、2 ファイルなら chip は 4 個ある（設計どおり）。

→ 入力欄の中だけを数えるようにし、控えとの合計も併せて確かめるようにした。

### 4-3. 私が AI 試験を同時に走らせた

非 AI だと思って 5 本の回帰スイートを走らせたが、
`vq2attach` / `vq2mock` / `vqregress` は**間接的に Bridge を叩く**（私の見落とし）。
実行中の `vq3mock` とぶつかり、BRIDGE_429 で 5 件が失敗した。

**単独で流し直したら全部通った**（`vq2mock` 11/11・`vqregress` 正常・`vq2attach` は §4-2 のみ）。
**AI を使う試験は、同時に 1 本だけ。** README に書いてあったのに私が破った。

## 7. 未解決

### 7-1. 解答がどの選択肢とも一致しない設問が残る

再測定（36 問）で 1 件。モデルの書いた解答が選択肢の文言・ID・記号のどれとも
一致せず、`repairSpec` が正解を書き当てられなかった（`noCorrectChoice`）。
保存は**正しく拒否**されるので誤った試験は世に出ないが、
その回は手で直すまで保存できない。

§3-2 で直した「解答が空」とは**別の経路**。今回は直していない。

### 7-2. 矛盾した答案が満点で通りうる

§3-b のとおり。指示を足しても改善が確かめられなかったため、**未解決**として残す。

### 7-3. 「新しい会話」ボタンが効かなくなることがある

- 長時間の自動操作（30 会話 ＋ 停止 ＋ 再送信 ＋ 連打）のあと、
  同じブラウザの**2 枚目のタブ**で、押しても会話が切り替わらなかった
- 次の条件では**毎回正常**だった
  - まっさらな状態で 1 タブ（送信 → 押す → 消える）
  - まっさらな状態で 2 タブ目
  - 会話を 84 件まで増やしてから 40 回連打
- **原因を特定できていない。** 自動操作に固有の可能性が高いが、断定できない

同じ種類の失敗が続いても根本原因に届かなかったので、
**危ない変更を重ねず、既知の問題として報告する**方を選んだ。
手で確かめてほしい（`V3_RELEASE_READINESS.md` §4-1）。
