# Quick Mock を速くした記録（2026-07-27）

「Quick と呼べる状態ではない（18〜40分かかる）」という指摘から。
**測っていないことは「未検証」と書く。** 数字はすべて同じ条件・同じ資料で取った。

計測: `node vqmockperf.cjs before|after [回数]` / `node vqmockperf.cjs compare`
機能: `node vqmockfast.cjs`（AI を実際に動かして中身を確かめる）

前後の切り替えは **`VQ_FAST_MOCK=0`**（最適化前）／ **`1`**（後）。
`local-ai/config/models.json` の `runtime.fastMock` でも切れる。
どちらも Bridge の再起動が必要。

条件: 資料1件・**大問3・設問9・100点・50分**。

## 2. 何が起きていたのか

### 2-1. 深い思考モデルの計画は、失敗する以前に「使われていなかった」

**全体の 36%（139.6秒）がこれ。** 未検証だが条件の大きい計測では 345 秒・45% だった。

計画から後段へ渡っているのは `requirements`（riskChecks）だけで、
それを読むのは `pipeline-text.mjs` **だけ**。Quick Mock が通る
`runStructuredPipeline` は `requirements` を**一度も参照していない**
（`grep requirements` で確認できる）。

つまり作った計画は**必ず捨てられていた**。にもかかわらず

  Thinking モデルの読み込み → 最大2,500トークンの思考 → 解放

を大問ごとに繰り返していた（解放しないと後段の生成でモデル再読み込みの
停止が起きる、と実装コメントにある。実測 90〜105 秒）。
そのうえ **2 回は計画の解析に失敗**していた（条件の大きい計測では 6 回）。

→ 構造化出力（Preset / Quick Mock）では計画を作らない。Thinking モデルにも触らない。

### 2-2. 頼んだ数の 3 倍近く作って、捨てていた

`mock-generator` は JSON Schema でモデルを縛っているのに、
`questions` 配列に **`maxItems` が無かった**。だから「4問作って」は
日本語のお願いでしかなく、モデルは好きなだけ返す（実装コメントに
「実測: 4問頼んで48問」とある）。

捨てていたのは**クライアント側**、つまり Bridge の全工程
（Schema検証・出典解決・**根拠確認のモデル呼び出し**・修正ループ）が
**66問すべてに対して走り終わったあと**。捨てた55問ぶんの生成時間も
検証時間も全部払っていた。

→ Schema に `minItems` / `maxItems` を入れた。指示ではなく**構造として**多く出せなくする。

### 2-3. 大問数も設問数も、指定が効いていなかった

「大問3・設問9」と指定しても、`sectionPlan()` は構成案（AI）が返した
大問数・設問数・配点を**そのまま採用**していた。検証済みの計測では
構成案が **4 大問・11 問**を返し、最終的に **12 問**の試験になっている
（指定は 9 問）。**遅いだけでなく、頼んだものと違うものが出てくる。**

→ 構成案から使うのは「何を出すか（見出し・題材）」だけにした。
　 いくつ・何点かは設定から機械的に割る（`sectionPlan` / `split`）。

### 2-4. 100点が100点にならない

2 か所あった。

1. `Math.round(100 / 3)` = 33点 × 3 = **99点**。割り切れない時点で満点に届かない
2. 大問ごとの呼び出しでも指示文に「満点: 100 点」が入るため、Bridge が
   **1 大問ぶんの合計を試験全体の満点と比べて**「依頼は100点でしたが
   合計は◯点です」と毎回警告していた

→ ① 最大剰余法で割る（`split`）。合計は必ず一致する。
　 ② `scoreAuthority: "client"` を追加し、配点をこちらで決めるときは
　 　 Bridge 側で満点と突き合わせない。最終的な配点は `SA.allocate` が
　 　 問題形式と難易度の重みで満点ちょうどに配る（**AI は配点に関与しない**）。

### 2-5. 同じ画像を大問の数だけ読み直していた

`skipDocumentAnalysis` は**資料の要点整理しか止めていなかった**。
`analyzeImages` は `orchestrate()` ごとに無条件で走るので、
5 大問なら同じ画像を 5 回 Vision へ流していた。
実測でも `document-analyst` が **4 回・31.0 秒**走っている（after は 1 回・3.1 秒）。

→ 1 回目の読み取り結果を `source_digest` として返し、
　 2 回目以降は `sourceDigest` を送り返す。届いていれば資料も画像も読み直さない。
　 添付が変わったらキャッシュは捨てる。

### 2-6. 全部が直列だった

`next()` の再帰で 1 大問ずつ。しかも 1 大問ごとに `orchestrate()` 丸ごと。
Bridge は同時 2 まで通せるのに、クライアントが 1 本ずつしか投げていなかった。

→ 資料の読み取りが済むまでは 1 本、済んだら Bridge の `maxConcurrent`
　 （既定 2）まで並列。**勝手に増やさない** — 同時実行数を上げると
　 エンジンの前で詰まって全員が遅くなるのは別途実測済み
　 （同時5で5人中1人が固まり1500秒）。

### 2-7. Critic / Verifier を全問に毎回かけていた

`verifyEvidence` は draft 全体の最大30件をまとめて 1 回で投げる作りだが、
大問ごとに呼ぶと**大問の数だけ**同じ確認を繰り返す。

→ 出典が決定論的に実在確認でき、解答も入っている設問は飛ばす。
　 残った「気になる設問」だけを投げる。0 件ならモデルを呼ばない。

## 3. 変えたところ

| 変更 | 場所 |
|---|---|
| 構造化出力では計画を作らない／Thinking に触らない | `orchestrator.mjs` |
| `minItems` / `maxItems` で作りすぎを構造的に禁止 | `roles/mock-generator.mjs` |
| 資料の読み取り結果を1回だけ作って渡す | `orchestrator.mjs`（`source_digest` / `sourceDigest`） |
| 満点との突き合わせを呼び出し側に委ねる | `pipeline-structured.mjs`（`scoreAuthority`） |
| 根拠確認を「気になる設問」だけに絞る | `pipeline-structured.mjs` |
| 工程別の時間・Token・再処理を SSE で返す | `server.mjs`（`metrics`） |
| 構成・設問数・配点をコード側で確定 | `client/index.html`（`sectionPlan` / `split`） |
| 大問の並列生成・逐次表示・生成中の操作 | `client/index.html`（`GEN` / `pump` / `paintPartial`） |
| 並列で停止ハンドルを潰し合わないように | `client/index.html`（`LocalAIProvider._active`） |

### 生成中にできること

止める以外の道を用意した。違うと気づいた時点で全部やり直す、をなくすため。

- **一時停止 / 再開** — 走っている大問は最後まで作ってから止まる
- **指示を追加** — これから作る大問にだけ効く。**できている大問は作り直さない**
- **未完成だけ作り直す** — できている大問には触らない
- **大問を名指しで作り直す** — 明示の指示があるときだけ
- できた大問はその場で画面に出る。**全部そろう前から編集できる**

### 未検証

- **1 条件・各 1 回しか測っていない。** p50 と p95 が同じ値なのはそのため。
  `node vqmockperf.cjs after 5` のように複数回まわさないと、ばらつきは分からない。
- 大きな資料（PDF・画像・複数ファイル）での計測はしていない。
  利用者が言っていた 18〜40 分は、おそらくもっと大きい入力での話。
  ここで測ったのはテキスト1件・9問の小さな試験。
- `exports/mockperf-before-unverified.json` は**条件が入っていない状態**で
  取ってしまったもの（771.9s）。比較には使えない。残してあるのは経緯のため。

## 5. 注意

- `vqmockperf.cjs` の完成判定は「生成中の操作バーが消えて、設問が出ている」。
  高速版は**できた大問から先に画面へ出す**ので、設問の出現だけで判定すると
  1 大問できた時点を完成と誤認する（実際に一度そうなった）。
- AI を使うテストは**同時に 1 本だけ**。
- `server.mjs` と `config/models.json` を変えたら **Bridge の再起動が必要**。
